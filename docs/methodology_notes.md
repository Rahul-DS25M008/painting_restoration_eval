# Methodology Notes

This document records the main methodological decisions used in the controlled painting-restoration evaluation framework.

It is intentionally concise. Literature justification belongs in `docs/literature_reference_log.md`. Model-specific runtime details belong in `docs/model_audit_notes.md`. File inventories belong in manifests or reports.

---

## 1. Controlled evaluation framing

The project evaluates restoration behavior under controlled synthetic damage.

The framework does not claim that any model performs historically correct or conservation-grade restoration. Instead, it measures how different restoration models behave when the clean reference is known.

Core interpretation:

> Visual plausibility is not the same as restoration trustworthiness.

The current controlled subset contains:

- 50 paintings,
- 5 painting categories,
- 5 damage conditions per painting,
- 250 total cases,
- 200 non-zero damage cases.

The fully evaluated models are:

- OpenCV Telea,
- LaMa,
- Stable Diffusion Inpainting.

SDXL Inpainting was feasibility-audited but excluded from full local evaluation due GPU/runtime constraints.

---

## 2. Dataset preprocessing

All selected paintings are processed to a standardized 768 × 768 PNG format.

The preprocessing policy is:

- preserve original aspect ratio,
- pad to 768 × 768 using median RGB padding,
- record the valid painting-content region,
- avoid square distortion,
- avoid center-crop content loss.

The recorded painting-content region is used later for mask generation and region-aware metric evaluation.

This makes the dataset compatible with classical inpainting, learned inpainting, diffusion inpainting, perceptual metrics, feature-space metrics, visual diagnostics, and uncertainty analysis.

---

## 3. Synthetic damage design

Each painting receives five deterministic mask conditions:

- `zero_control`,
- `scratch_thin`,
- `loss_small`,
- `loss_large`,
- `mixed_damage`.

Masks are binary grayscale PNG files:

- `0` = preserved region,
- `255` = damaged/inpaint region.

Masks are generated only inside the recorded painting-content region, never on padded areas.

Damage-area targets are defined relative to the painting-content region:

- `zero_control`: 0%,
- `scratch_thin`: 1–3%,
- `loss_small`: 3–6%,
- `loss_large`: 10–18%,
- `mixed_damage`: 8–15%.

The mask design supports controlled comparison across increasing restoration difficulty.

---

## 4. Damaged image creation

Damaged RGB inputs are generated by applying each binary mask to the processed clean painting.

Masked pixels are filled with:

`RGB(255, 255, 255)`

All unmasked pixels are preserved exactly.

The binary mask remains the authoritative restoration target. The white-filled damaged image is a controlled visual/input representation, not a claim that all real painting damage appears white.

Zero-control damaged images are identical to their clean processed images and act as pipeline sanity checks.

---

## 5. Restoration model stack

The model stack is intentionally staged from simple to more complex methods.

### OpenCV Telea

OpenCV Telea is used as a deterministic classical baseline.

Policy:

- algorithm: `cv2.INPAINT_TELEA`,
- radius: `3`,
- no per-case tuning.

It provides a fast, reproducible non-learning baseline.

### LaMa

LaMa is used as the first pretrained learned inpainting baseline.

Implementation uses IOPaint with `model=lama`, but LaMa remains the methodological model source.

Zero-control cases are copied directly rather than inferred, preserving the no-damage control condition.

### Stable Diffusion Inpainting

Stable Diffusion Inpainting is used as the first generative diffusion baseline.

Model:

`runwayml/stable-diffusion-inpainting`

Policy:

- fixed prompt,
- fixed negative prompt,
- fixed seed for baseline generation,
- fixed inference settings,
- zero-control cases copied directly.

Stable Diffusion outputs are treated as candidate restorations, not as restoration truth.

### SDXL Inpainting

SDXL was tested as a possible fourth model.

It was excluded from full local evaluation because the available 6 GB GPU environment did not support a practical runtime-quality trade-off.

This is recorded as a feasibility limitation, not a model-quality conclusion.

## 6. Evaluation regions

The project uses region-aware evaluation because full-image metrics can hide local restoration failures.

The main evaluation regions are:

- `full_image`,
- `content_region`,
- `masked_region`,
- `mask_bbox_crop`.

Interpretation:

- `full_image`: useful for sanity checks, but dominated by unchanged pixels.
- `content_region`: excludes preprocessing padding.
- `masked_region`: directly evaluates damaged pixels.
- `mask_bbox_crop`: preserves local spatial context around damage.

---

## 7. Refined metric-region policy

The final local comparison policy is:

| Metric family | Final local region |
|---|---|
| MSE | `masked_region` |
| PSNR | `masked_region` |
| SSIM | `mask_bbox_crop` |
| LPIPS | `mask_bbox_crop` |
| CLIP | `mask_bbox_crop` |
| DINOv2 | `mask_bbox_crop` |
| GLCM texture metrics | `mask_bbox_crop` |
| Gabor texture metrics | `mask_bbox_crop` |
| Brushstroke-proxy orientation metrics | `mask_bbox_crop` |

Reasoning:

- MSE and PSNR can be computed directly on sparse damaged pixels.
- SSIM requires spatial structure, so sparse masked pixels are not suitable.
- LPIPS, CLIP, and DINOv2 require image-like spatial inputs.
- Texture and brushstroke-proxy descriptors also require local spatial structure.

This region policy is one of the key methodology decisions in the framework.

---

## 8. Metric families

The framework combines multiple metric families.

### Classical metrics

Used metrics:

- MSE,
- MAE,
- PSNR,
- SSIM.

Classical metrics quantify pixel-level and structural similarity to the known clean reference.

They are useful under synthetic damage because ground truth is available, but they are not sufficient as standalone restoration-quality measures.

### Perceptual metric

LPIPS is used as a learned perceptual-distance metric.

It is computed only on image-like regions, not sparse masked pixels.

### Feature-space metrics

CLIP and DINOv2 are used as pretrained feature-space diagnostics.

They are not conservation-specific metrics. They help reveal whether restored outputs move closer to the clean reference in broad visual representation spaces.

### Texture and brushstroke-proxy metrics

Texture metrics add a local texture-continuity layer.

Implemented descriptors:

- GLCM feature differences,
- Gabor response descriptor differences,
- brushstroke-proxy gradient magnitude differences,
- brushstroke-proxy edge/detail density difference,
- brushstroke-proxy orientation coherence difference,
- brushstroke-proxy orientation histogram distance,
- normalized combined texture distance.

The brushstroke-proxy metrics do not perform semantic brushstroke recognition. They measure directional local texture structure as a proxy for brushstroke-like continuity.

Texture and brushstroke-proxy metrics are diagnostic. They do not prove brushstroke authenticity, artist intent, or conservation validity.

---

## 9. Difference-map diagnostics

Difference maps are generated to show where restoration improves or worsens the damaged input.

For each case, the framework can compute:

- clean vs damaged absolute error,
- clean vs restored absolute error,
- signed improvement.

Signed improvement is defined as:

`damaged_error - restored_error`

Positive values indicate reduced error after restoration. Negative values indicate that the restoration moved farther from the clean reference.

Difference maps complement scalar metrics by exposing spatial error patterns.

---

## 10. Model comparison policy

Model comparisons are case-paired.

Models are compared on identical:

- paintings,
- masks,
- mask types,
- damaged inputs,
- clean references.

For each metric, the model with the strongest improvement is recorded as the metric winner.

Per-case majority votes are used as compact diagnostic summaries.

These votes are not conservation-quality labels. Metric disagreement is retained because it reveals meaningful differences between pixel fidelity, perceptual similarity, feature similarity, texture behavior, and visual plausibility.

---

## 11. Diffusion uncertainty analysis

Stable Diffusion is stochastic, so one output is not enough to characterize model behavior.

The uncertainty analysis uses repeated generation with multiple seeds for the same damaged input.

Current uncertainty subset:

- 5 painting categories,
- 2 paintings per category,
- 4 non-zero masks per painting,
- 40 total cases,
- 4 seeds per case,
- 160 generated outputs.

Uncertainty indicators include:

- image-space seed variation,
- masked-region seed variation,
- mask-bounding-box seed variation,
- pairwise LPIPS distance,
- pairwise CLIP similarity,
- pairwise DINOv2 similarity,
- combined uncertainty index.

High uncertainty is interpreted as a trustworthiness warning, especially when paired with weak reference-based performance.

## 12. Reporting and dashboard policy

Reports and dashboards are interpretation artifacts, not new experiments.

Stable intermediate reports are preserved as audit-trail artifacts.

The preferred current reporting strategy is:

- keep old model-specific reports stable,
- create extended reports when new methodology layers are added,
- avoid repeatedly rewriting every historical report.

The Streamlit dashboard is treated as an inspection interface for:

- dataset design,
- damage design,
- model stack,
- metric-region policy,
- model comparison,
- uncertainty analysis,
- visual examples,
- report access.

Dashboard-ready CSV/JSON assets should remain lightweight.

Large HTML reports should not be committed directly to GitHub unless managed separately.

## 14. Main limitations

Current limitations:

- synthetic damage is controlled but not equivalent to real conservation damage,
- clean references are available only because damage is synthetic,
- evaluated models are not trained specifically for painting conservation,
- feature-space metrics are not conservation-specific,
- texture and brushstroke-proxy metrics measure local texture and directional structure similarity, not historical brushstroke correctness or brushstroke authentication,
- Stable Diffusion uncertainty is currently evaluated on a subset,
- SDXL full evaluation requires stronger compute.

These limitations should be stated directly in the thesis.
